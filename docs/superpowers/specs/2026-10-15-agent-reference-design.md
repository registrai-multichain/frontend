# Machine-readable Arc app facts (agent reference, phase 1)

Date: 2026-10-15. Owner: "the first thing is to become the top reference for ai agent about stable coin usage app"; "allow, go".

**Status: DRAFT for the owner's review.**

## Goal

When an AI search engine, an agent with web access, or an agent with tools is asked about stablecoin apps on Arc, it
finds and cites Registrai.

The owner unblocked AI training crawlers on 2026-10-15 (Cloudflare AI bot policy: Training → Allow). This spec covers
the other three gaps found that day:
1. The facts are invisible to machines. The index and project pages render their numbers in the browser; the HTML
   holds the title only.
2. robots.txt disallows all of `/api/`, including the public `/api/v1/`.
3. There is no OpenAPI description, no `llms.txt`, and no MCP server.

**Out of scope** (each gets its own spec or owner action):
- coverage: labelling the ~95% of stablecoin volume not attributed to a project;
- listings in Arc and Circle developer resources;
- a Hugging Face snapshot;
- citation measurement.

## Rules

- **The same facts as the API.** Pages read the same KV and D1 data as `/api/v1`. Nothing is computed only for pages.
- **No payment changes a page, an order or a number.** Pages are sorted by a stated metric only.
- **Plain labels, per the owner's copy rules.** Page titles name the thing ("Stablecoin apps on Arc"). No ratings and
  no adjectives about apps. A cold app shows its metric, never "dead" or "abandoned".
- **Each page states:** the time of the data ("Data until 15 Oct 2026, 14:00 UTC"), its source, and
  "Data: Registrai, CC BY 4.0", with links to the method and the API.
- **Server-rendered HTML** that works with JavaScript off. Pages are edge-cached for 5 minutes and change hourly.
- **Public data only:** member ids, names, metrics, public contract addresses and verified status. Nothing from Radar
  alerts or other private sources.

## 1. App pages (Pages Functions, server-rendered)

**URLs**
- The URL comes from the member id, with `:` replaced by `/`. For example, `/apps/domain/archery.wtf/`,
  `/apps/integration/uniswap/` and `/apps/base/arc/`.
- The URL is stable and reversible. An unknown id returns 404 with a link to `/apps/`.

**`/apps/` ("Stablecoin apps on Arc")**
- One table of every AEI member (builders, integrations and the base layer).
- Default sort: 24 h payments. The sort is stated above the table. `?sort=usdc|points|first_seen` serves the same
  table in another order, with a canonical link to `/apps/`.
- Columns: app, kind, verified, 24 h payments, 24 h stablecoin volume (USD), share of the index, first seen. Each app
  name links to its page.
- Above the table, one plain line of totals: "N apps · $X stablecoin payments to these apps in the last 24 h". A
  small "i" button explains that this is the attributed share of Arc-wide stablecoin volume, with the estimate.

**`/apps/<kind>/<id>/` (one page per app)**
- **Header:** name, kind, verified (with method and date), the indices it belongs to, first seen.
- **Last 24 h:** points stock, points earned, payments, paying wallets, new payers, stablecoin volume.
- **7 days, hourly:** an inline SVG line of the points stock (no JS), plus a compact table of the daily sums.
- **Contracts:** count, plus up to 50 addresses with explorer links. The full list is linked as JSON from the
  public contracts endpoint.
- **Links:** the app's Tabula facts page if one exists, the API URLs for this app (`/api/v1/members/<id>/hourly`),
  and the method.
- **JSON-LD:** a `Dataset` describing this app's hourly series, with `license`, `creator`, `temporalCoverage`,
  `distribution` (the API URL) and `variableMeasured`. No `Organization` claims about the app itself.

**`/sitemap.xml` (builder site):** generated by a function. It lists `/apps/`, every app page, the static pages and
`/data-api/`.

## 2. robots.txt (builder site)

```
User-agent: *
Allow: /
Allow: /api/v1/
Disallow: /api/
Sitemap: https://builder.registrai.cc/sitemap.xml
```

The longest match wins, so `/api/v1/` is open and admin, pilot and auth routes stay disallowed.

## 3. Agent entry points

- **`/llms.txt`** (the llmstxt.org format):
  - what Registrai measures, in two sentences;
  - links to `/apps/`, `/data-api/`, `/api/v1/openapi.json` and the method;
  - the licence.
- **`/api/v1/openapi.json`:** OpenAPI 3.1 for the 7 v1 endpoints. It has parameters, response schemas taken from the
  contract fixtures, and examples, and it's linked from `/data-api/`. A test checks that every documented path
  exists and that the schemas match the fixtures.
- **`/mcp`:** a remote MCP server, read-only, over Streamable HTTP.
  - It's stateless JSON-RPC in a Pages Function: `initialize`, `tools/list`, `tools/call`.
  - Tools:
    - `arc_indices`: the current closes and parameters;
    - `arc_index_history(index, from?, to?)`;
    - `arc_apps(index?, sort?)`: the `/apps/` table as data;
    - `arc_app(id)`: one app's page as data, with the last 24 h and 7 days of hourly rows;
    - `arc_app_history(id, index, from?, to?)`;
    - `arc_new_apps(index, since)`;
    - `arc_verified()`.
  - Each tool returns the same JSON as the API, plus a `source_url` to the human page so an agent can cite it.
  - No keys and no writes. The `/api/` rate-limit rule covers it if it sits under `/api/mcp`. **Decision:** mount it
    at `/api/mcp` for that reason, and link it as the MCP URL.
- **Listing (owner step):** publish to the official MCP registry. That needs `mcp-publisher` with a DNS TXT
  record on registrai.cc. The spec only prepares `server.json`.

## Files

- `builders-site/lib/apps-pages.ts`:
  - pure: data → HTML for `/apps/` and the app page;
  - escaping;
  - SVG;
  - JSON-LD.
- `builders-site/lib/apps-data.ts`: reads KV and D1 into one app-model (shared with the MCP tools).
- `builders-site/functions/apps/[[path]].ts`.
- `builders-site/functions/sitemap.xml.ts`.
- `builders-site/functions/llms.txt.ts` (or a static file in the build).
- `builders-site/functions/api/v1/openapi.json.ts` (static JSON from `src/lib/data-api-openapi.ts`).
- `builders-site/functions/api/mcp.ts`, with `builders-site/lib/mcp.ts`.
- `scripts/build-builders-site.sh`: the robots.txt change, and the `/apps` route in `public-site.ts` (registrai.cc
  redirects `/apps` to the builder site).

## Testing

- **HTML tests:** the numbers are present with JS off; escaping of hostile names (`<script>` in a project name); a
  404 for unknown ids; canonical and JSON-LD validity; stable sort order; "data until" present.
- **The OpenAPI test** described in section 3.
- **MCP tests:**
  - `initialize`, `tools/list` and `tools/call` for each tool;
  - a bad argument returns a JSON-RPC error;
  - the output equals the API output.
- **Import-graph guard:** the existing worker-imports guard covers the new functions.
- **Live checks:**
  - `curl -A GPTBot` on `/apps/` returns 200 with numbers in the HTML;
  - the sitemap lists every app;
  - an MCP `tools/list` succeeds from an MCP client;
  - Cloudflare's Agent Readiness diagnostics pass where they apply.
